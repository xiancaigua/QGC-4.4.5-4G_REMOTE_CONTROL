# 用户手动选择 RC 或 4G 的控制设计草案

日期：2026-11-26。目标飞控 PX4 1.13.3，G20 通过独立无线电链路将 SBUS/RC 送至飞控；Windows QGC 通过 HyperLTE 厂商云 TCP 链路传 MAVLink。当前键盘面板已实现手动发 `MANUAL_CONTROL`，下述 RC 仲裁与授权流程**尚未开发或验证**。

## 两类控制权

- **持续摇杆控制**：G20 的 SBUS 与 QGC 的 `MANUAL_CONTROL` 争用 PX4 手动控制源。默认由 RC 控制；两路均有效时由操作员明确选择，系统不因 RC 恢复而自动抢占。键盘只有在安全授权且飞控确实选中 MAVLink 输入后才显示“已接管”。
- **离散命令**：航线上传、开始/暂停任务、切换模式、返航是单条 MAVLink 命令，不受“RC 摇杆优先”自动约束。需要独立的操作权限与确认；不能把 RC 摇杆优先误当成所有 4G 命令都被禁止。

## 状态与动作

| 状态 | 计划动作 |
| --- | --- |
| RC 有效，4G 有效 | 默认 RC 控制；QGC 可看遥测和视频。若人工选择 4G，须 RC 操作者授权、电脑操作者再次确认，并由飞控侧完成源切换且报告结果。反向切回 RC 同样由操作员发起；不自动抢占。 |
| RC 无效，4G 有效 | 显示“RC 已失效”，电脑操作者进行简化确认后方可启用键盘；先核验链路质量与飞控实际选择的输入源。 |
| RC 恢复，4G 键盘工作 | 不因 RC 恢复而自动切换。若操作员选择 RC，先停发键盘并清零键位，再等待飞控确认选中 RC。 |
| 4G 失效，RC 有效 | 4G 摇杆停止。若当前由 4G 控制，RC 操作者应能通过经验证的机载源选择机制接管；在该机制存在前，依靠飞控失联保护，不能假设 RC 已自动接管。航线模式的失联返航另行配置。 |
| RC 与 4G 均失效 | 由飞控失联保护执行 Hold/Return 等动作；地面 QGC 已断线，无法可靠地下发新命令。 |
| 4G 抖动或仅单向可达 | 禁止新启用键盘；已启用时停止发送并依靠机载超时保护。下行遥测正常不能证明上行控制成功。 |

## PX4 1.13.3 的限制

PX4 v1.13.3 `ManualControlSelector.cpp` 中 `COM_RC_IN_MODE=2` 接受任一有效输入，但保持当前输入直到超时；`=3` 锁定最先有效的输入。两者都没有“操作员点按钮、两路都有效时切换当前源”的机制。若要在 **RC 与键盘同时在线** 时按用户决定切换，仍需飞控侧实现明确的源选择（改动/升级固件，或经验证的机载仲裁网关）；仅改 Windows QGC 的按钮不能保证飞控真正切换。切换参数 `COM_RC_IN_MODE=0/1` 会禁用另一输入，不宜直接作为飞行中的交接机制。

在保持 PX4 1.13.3 不改动时，`COM_RC_IN_MODE=2` 可以作为**试验性失效回退方案**：当前源失效后允许另一有效源接替；不能实现两路健康时的主动切换。该模式可用于台架验证，但不能把 QGC 界面的“已选 4G”当作飞控已接管的证据。正式方案需要定义双端握手、超时、切换后的确认和断线处理，再在 SITL 与无桨台架验证。
